# 项目执行资产规则 V0.8

目标：**让后续项目先复用已有有效信息，再做增量工作。**

## 最小记录范围

每个项目阶段只记录五件事：

1. 目标：要解决什么、验收是什么、不做什么。
2. Preflight：运行时、依赖、测试框架是否可用。
3. 计划：主要步骤、涉及哪些共享模块。
4. 有效证据：测试、E2E、审计、扫描、度量、Manifest 中真正影响结论的数据。
5. 可复用结论：别人以后可以直接引用的结论及失效条件。

不要求保存完整执行过程。

## 开始任务

固定顺序：

```text
查 EXECUTION_ASSET_INDEX
        ↓
复用已有 ACTIVE 资产
        ↓
Preflight
运行时 → 依赖 → 测试框架
        ↓
PASS？
 ┌──────┴──────┐
 YES           NO
  ↓             ↓
正式执行      环境熔断
```

Preflight 未通过时：
- 不进入代码修改；
- 不把环境失败判定为代码失败；
- 记录阻断事实和恢复动作；
- 环境恢复后原样重跑任务。

## 结束任务

只归档满足至少一个条件的内容：

- 会影响后续设计决策；
- 能减少后续重复测试或审计；
- 能证明某个组件已验证；
- 能明确已知风险或边界；
- 能作为下一阶段验收输入；
- 会导致同类任务重复失败的环境事实。

临时日志、重复截图、探索过程、可随时重新生成的中间清单默认不归档。

## 失效原则

资产只在明确触发条件下失效，例如：

- 相关代码发生实质变化；
- Contract / Schema / API 改版；
- 需求改变；
- 真实 E2E 与原结论冲突；
- 架构决策被正式替换；
- 执行环境或依赖基线已恢复/变更。

失效后更新原资产状态，不复制一份相同结论。
