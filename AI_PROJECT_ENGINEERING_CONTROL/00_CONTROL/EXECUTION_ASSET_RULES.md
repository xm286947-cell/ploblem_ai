# 项目执行资产规则 V0.5

目标：**让后续项目先复用已有有效信息，再做增量工作。**

## 最小记录范围

每个项目阶段只记录四件事：

1. 目标：要解决什么、验收是什么、不做什么。
2. 计划：主要步骤、涉及哪些共享模块。
3. 有效证据：测试、E2E、审计、扫描、度量、Manifest 中真正影响结论的数据。
4. 可复用结论：别人以后可以直接引用的结论及失效条件。

不要求保存完整执行过程。

## 开始任务

```text
查 EXECUTION_ASSET_INDEX
        ↓
命中 ACTIVE 资产
        ↓
判断是否触发失效条件
        ↓
未失效 → 直接复用
已失效 → 只验证变化部分
```

禁止因为“换了一个项目”就重新做同一份全仓审计。

## 结束任务

只归档满足至少一个条件的内容：

- 会影响后续设计决策；
- 能减少后续重复测试或审计；
- 能证明某个组件已验证；
- 能明确已知风险或边界；
- 能作为下一阶段验收输入。

临时日志、重复截图、探索过程、可随时重新生成的中间清单默认不归档。

## 失效原则

资产只在明确触发条件下失效，例如：

- 相关代码发生实质变化；
- Contract / Schema / API 改版；
- 需求改变；
- 真实 E2E 与原结论冲突；
- 架构决策被正式替换。

失效后更新原资产状态，不复制一份相同结论。
