# REQ-013 低质量批量问题的数据集隔离与分析

状态：`TRIAGED`

优先级：`P1`

来源：2026-08-31 批量问题分析需求

## 背景

需要导入一批数据质量较低的问题进行批量 AI 分析。这些数据具有分析价值，但字段缺失、口径不统一、结论可信度不足，不能默认混入当前正式问题库，否则会污染问题数量、质量洞察、产品报告、能力缺口和治理结论。

## 核心决策

采用“数据集/问题组”作为隔离边界：

```text
上传低质量批量数据
→ 创建隔离数据集
→ Mapping与数据质量预检
→ 数据集内批量AI分析
→ 人工评审
→ 选择性纳入正式问题库
```

低质量数据默认不进入正式统计口径。只有完成确认或执行“纳入正式库”后，才参与现有问题工作台默认视图、质量洞察和产品综合报告。

## 数据集信息

每个数据集至少记录：

- 数据集编号、名称和说明。
- 来源文件、来源系统和上传批次。
- 业务/产品及时间范围。
- 数据负责人、创建人和创建时间。
- 数据质量等级：`HIGH / MEDIUM / LOW / UNKNOWN`。
- 使用目的：探索分析、专项分析、历史补录或正式接入。
- 隔离级别：`ISOLATED / OFFICIAL`。
- 当前状态：`DRAFT / READY / ANALYZING / REVIEW_REQUIRED / REVIEWED / PROMOTED / ARCHIVED`。
- 总行数、有效问题数、缺失率、重复率、Mapping覆盖率和AI分析覆盖率。

## 隔离规则

1. 现有正式问题归属默认数据集 `OFFICIAL_DEFAULT`。
2. 新建低质量批量数据默认归属 `ISOLATED` 数据集。
3. 正式问题工作台、质量洞察和产品报告默认只读取 `OFFICIAL`。
4. 用户主动选择隔离数据集后，页面必须显示明显的“隔离数据/非正式口径”提示。
5. 隔离数据不得影响正式问题总数、TOP原因、能力缺口和报告结论。
6. 批量AI任务必须绑定单一数据集，进度、错误和结果按数据集统计。
7. 数据集归档不删除原始文件、Raw记录、分析结果和人工确认记录。

## 分析方式

数据集内部支持：

- 字段覆盖率和数据质量报告。
- 仅分析满足最低字段条件的问题。
- 对字段不足的问题标记 `INSUFFICIENT_DATA`，不得强行生成确定性结论。
- 批量选择模型、并发数、问题领域和生命周期预设。
- 查看成功、失败、待确认和因数据不足跳过的问题。
- 生成仅针对该数据集的临时综合报告。

## 人工纳入正式库

人工评审后支持按问题选择：

- `PROMOTE`：纳入正式问题库。
- `KEEP_ISOLATED`：保留在隔离数据集继续分析。
- `REJECT`：判定无效，但保留审计记录。
- `MERGE`：与正式库已有问题合并，避免重复。

纳入时必须重新执行必填字段、业务主键、Mapping版本、重复问题和数据质量校验。纳入操作记录操作者、时间、原因、原数据集和目标问题编号。

## 推荐实现边界

近期优先采用逻辑隔离，不单独建立第二个数据库：

- 新增数据集表和“问题—数据集”关联扩展表。
- 不重写现有问题、Mapping和AI分析主结构。
- 正式查询统一增加默认 `OFFICIAL` 范围。
- 数据量或权限要求提高后，再评估物理库/Schema隔离。

这样既能保持现有功能稳定，也能避免维护两套完全不同的导入和分析系统。

## 页面与业务入口

新增“批量问题数据集”工作台：

1. 数据集列表与质量状态。
2. 新建数据集并上传文件。
3. Mapping Preview与数据质量预检。
4. 数据集问题清单。
5. 批量AI分析进度与结果。
6. 人工评审和纳入正式库。
7. 数据集临时综合报告。

现有正式问题工作台不改变默认业务流，只增加明确的数据范围提示和必要的切换入口。

## 验收条件

1. 导入隔离数据后，正式问题总数和质量洞察指标不变化。
2. 同一数据集中的问题可以独立批量分析和生成临时报告。
3. 数据不足的问题显示缺失项，不伪造根因或能力结论。
4. 支持单条和批量纳入正式库。
5. 纳入后正式问题库、洞察和报告按规则更新。
6. 重复问题可以合并，不产生两个正式问题。
7. 数据集、问题、分析运行和纳入操作均可追溯。
8. 现有导入、Mapping、问题分析和质量洞察回归为零失败。

## 暂不包含

- 不立即拆分独立数据库。
- 不允许隔离数据默认参与公司级质量指标。
- 不要求低质量数据在导入时全部补齐。
- 不自动将AI推断结果作为正式事实写入正式库。
