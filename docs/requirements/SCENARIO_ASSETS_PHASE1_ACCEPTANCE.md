# 质量场景库第一阶段实现记录

以本轮用户交接为当前范围。治理闭环、现场简易录入、产品版本质量趋势暂缓。

## M0 核对与复用

- 复用 quality_scenario、quality_scenario_evidence、产品场景词典、问题当前版本统计年月、ITR彻底解决单关联、base.html与既有样式。
- 既有逐问题AI识别是原始候选入口，不等于一问题一正式质量场景。正式资产支持人工多问题归集，保留源候选，可撤销归集。
- 软件使用场景允许暂缺，作为增量上下文保存，避免强制补造事实。

## M1—M5 实现

- /quality-scenario-assets：资产总览、筛选、分布、可切换交叉矩阵及时间分析。
- /quality-scenario-assets/{id}：业务链路、上下文维护、归集与撤销、来源问题、质量指标及测试消费建议。
- 新增三张隔离扩展表：scenario_asset_context、scenario_asset_member、scenario_asset_metric。
- 使用场景补充输入资源、环境工况、极限工况、业务目标、输出结果、约束、痛点、规模数值及单位；复用既有系统对象/规模/用户字段。
- 一场景多指标：关注点、可观察表现、方法、数据来源、口径、目标、评价与测试规格。当前为建议状态，没有伪造测量结果或达标结论。
- 趋势统一称“场景问题趋势”，使用当前问题year/month字段，支持季度/半年度/年度；缺失时间单列，不从场景创建时间推断。
- 通过行业/客户等筛选和时间作为交叉维度，支持季度×行业×场景等组合分析。

## 统计口径

- 按问题业务编号去重，ITR与末尾CS规范为同一问题；无业务编号使用knowledge_id。
- 行业、客户、型号优先关联彻底解决单，未关联时使用当前问题字段；不把场景聚合范围与每个来源问题做笛卡尔展开。
- 场景数量按归集后资产计数；场景明细保留全部候选及问题来源。
- 不同单位规模分开统计；当前支持明确数值+单位和原文分组，尚不自动抽取多个规模参数或拟合风险随规模增长的关系。
- 无装机量/使用次数等分母，所有数量只表达样本问题分布，不宣称故障率或产品质量改善。

## 验收与边界

- 使用临时SQLite与合成问题，验证归集证据保留、去重、行业客户交叉过滤、时间分桶、指标必填链路、页面访问和归集撤销。
- 自动AI聚类/自动发布未启用；复用既有逐问题识别，通过人工归集形成正式资产。
- 当前软件场景为附属上下文，独立软件场景多对多资产管理可在后续有真实复用需求时扩展。
- 服务人员现场入口、实际指标采集、测试平台集成和治理行动不属于本次。
- 修复已发现的行业变体更新误删能力缺口语句。
- 2026-09-05 本地全量回归：446 passed（tests目录）。浏览器检查新入口及空态布局；真实内部数据、外部AI调用和Windows BAT运行未在本机验证。
- 全部状态包含候选，使用“资产状态=已发布”查看正式资产；矩阵单元格下钻保持交叉条件并列出命中问题，详情展示资产全部证据。
