# 当前阶段唯一执行基线：客户质量场景画像 Demo

更新时间：2026-09-07。当前状态：开发收口。

## 唯一目标

短期不建设完整质量场景平台。当前只完成一个可演示、可追溯、有明确结论的客户质量场景画像 Demo，证明历史问题经过场景组织后，能够回答：客户怎么使用、涉及什么系统设备、处于什么环境工况、主要痛在哪里，以及研发和测试下一步应核查什么。

固定样板范围：锂电行业、先导公司、2026 年、软件与硬件。真实数据不足时使用明确标记的合成数据，不冒充客户事实。

## Demo 主链路

行业/客户/年份/月份/领域/产品联动筛选 → 数据库问题数量与去重对账 → 人工触发逐问题 AI 提取 → 分层归并 → 2～6 张画像主题卡片 → 原始问题证据下钻。

画像卡片固定展示：生命周期与业务活动、客户怎么用、系统/设备、系统规模、环境/工况、客户质量关注、客户语言痛点、业务影响、研发/测试核查、来源问题、信息缺口。

## 固定规则

- 画像直接查询彻底解决单/ITR；是否已有场景不决定问题能否被查到。
- CS 优先，ITR 补充；同一标准 ITR 只计一个问题。
- 系统/设备只从产品、型号、设备编码和设备名称等结构化信息获取。
- 环境/工况从问题描述、原因定位、TRC及现场记录中提取，必须保留来源；缺失不得补成事实。
- Agent 逐问题处理后再归并；已完成步骤复用，失败步骤可继续。
- 事实、AI 归纳、信息缺失明确区分；不自动发布场景，不自动认定风险等级。
- 问题数仅表示关注集中度；没有装机量和使用次数时不计算故障率。

## 当前只开发

1. 画像筛选与问题范围数量闭合。
2. 画像型 Agent 输出与证据覆盖。
3. “结论＋画像卡片＋证据下钻”页面。
4. 固定样板的合成回归和真实脱敏数据人工验收说明。

## 暂不开发

正式场景发布治理、部门审批、现场移动录入、质量指标闭环、版本质量评价、完整装机拓扑、Docker/MySQL迁移以及全量客户画像。

## 完成门槛

- 原始记录、冲突记录、去重后问题、筛选排除、进入 Agent、已完成、失败和未归纳数量能够对账。
- 每个进入 Agent 的问题都出现在某个画像主题或“尚不能归纳”中。
- 页面能在五分钟内完成固定范围选择、形成画像、查看主要矛盾并下钻证据。
- 至少两个画像主题给出有证据的研发和测试核查建议。

长期规划只作为背景；不得用正式版本建设替代以上 Demo 目标。
