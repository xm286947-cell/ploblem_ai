# PATCH55：客户/行业画像最终归并上下文预算修复

## 问题

客户/行业画像在完成逐问题提取和前序分层归并后，最后一次归并仍可能把过长的分批摘要一次提交给模型。实测请求总 Token 可达到 25938，超过部分模型的上下文窗口，任务在最后一步失败。

## 修复

- 归并前生成仅用于模型传输的紧凑视图，原始问题、已保存的中间结果和来源证据不被改写；
- 压缩重复的中间摘要和长段落，但完整保留每个主题及全部来源问题 ID；
- 归并树从最多 5 层扩展为最多 12 层，超长历史批次自动继续做二叉归并；
- 每次归并请求增加 15000 字符的硬预算，禁止再次发送超预算请求；
- 归并调用最多预留 6144 输出 Token，避免“输入 + 最大输出预留”共同挤爆模型上下文；
- JSON 紧凑重试与当前层主题数、字段长度限制保持一致；
- 失败诊断明确显示“模型输入/上下文预算超限”，不再误报为普通内容校验失败；
- 断点续跑继续复用已完成的逐问题结果和前序归并，只补跑失败层及后续层。

## 验收

1. 两份各含 5 个超长画像主题的历史归并结果，进入最终归并时请求不超过安全预算；
2. 紧凑视图与原结果包含完全相同的来源问题 ID；
3. 第三层失败后继续执行，只调用失败步骤，不重跑前 24 个已完成步骤；
4. 综合解读专项测试 19 条通过；主测试目录 510 条通过。

## 使用

升级后，对原失败画像点击“从失败步骤继续”。无需重新执行已完成的单问题提取和前序归并；如输入数据范围发生变化，系统仍按既有规则新建任务。
