# AI候选与行业／客户画像直接取数 PATCH39 交付说明

## 修复的问题

1. AI质量场景候选的选题范围改为只读取“软件问题考核工作台”的最新有效记录。彻底解决单、ITR和漏测分析只在选题完成后补充证据，缺失或冲突不得缩小候选问题数量。
2. 候选页增加数据库对账口径：软件考核原始记录、按工作台与标准ITR去重后的问题、历史版本以及当前筛选命中数。页面展示的范围和提交生成的范围使用同一查询函数。
3. 客户／行业画像改为按所选行业、客户／公司、产品型号和问题领域直接查询彻底解决单／ITR数据库。已有质量场景不再是画像取数入口，只标记问题是否已经沉淀为场景并提供补充信息。
4. 画像只保留一个人工触发按钮。AI处理数据库命中的全部去重问题；有场景的携带场景信息，无场景的从问题事实提炼并标记待评审，不自动发布场景。
5. 画像采用一问题一次AI解析、分层归并和最终全覆盖校验，避免大范围问题因上下文上限被静默遗漏。页面预览不逐问题读取四阶段AI分析，减少大数据库下的重复查询。
6. 修复考核年份优先级错误：过去自动从ITR编号写入的年份会遮蔽“数据运营_KPI计入月份”中的真实年份，导致按考核年份筛选时只剩少量人工修正记录。现统一为“人工指定 > KPI年月 > 文件年份 > ITR年份兜底”，已有数据无需重新导入。

## 业务口径

- 软件场景候选：以软件问题考核工作台和KPI计入年月为唯一选题口径。
- 行业／客户画像：以彻底解决单优先、ITR补空后的同号去重问题为范围。
- 已有场景：仅表示该问题已有可复用的场景资产，不决定问题是否进入画像。
- 未有场景：仍进入画像分析，但结果是待人工评审的AI提炼，不直接写入正式场景库。

## 验收

- 构造275个软件考核问题和1条历史版本，候选范围完整返回275个问题，对账显示276条原始记录、275个去重问题和1条历史版本。
- 构造只有彻底解决单、没有质量场景的行业客户问题，画像页面仍能直接查到并进入AI输入范围。
- 构造ITR年份为2025、KPI年月为2026-02且历史自动年份为2025的数据，工作台及AI候选按2026正确命中。
- 全量自动化测试：485项通过。
