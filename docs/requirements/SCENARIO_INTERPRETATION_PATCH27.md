# PATCH27：考核时间与综合解读

> PATCH28 打包修正：累计升级包自动包含全部网页模板，补齐 `association_settings.html`；功能实现不变。

## 已实现

- 历史 QK 问题与软件考核按规范化 ITR 关联，读取最新 KPI 计入年月，CS 后缀不影响匹配。
- 年月完整、月份缺失、缺年份、未关联等情况分别显示；不以提单年份或场景发布日期补齐统计时间。
- 场景工况优先人工输入，否则消费已有前置/触发条件原文，明确来源，不能据此声称已确认标准工况。
- “场景资产与业务洞察”应用筛选后，人工生成本范围综合解读；仅使用默认模型，不重跑单问题分析。
- 输入包含已有漏测分析、彻底解决单事实/根因/TRC纠正信息、场景链路和度量建议。缺漏测原因不可编造。
- 分批分析后分层归并。输出问题ID必须全部覆盖于主题或待归纳清单，拒绝遗漏及不存在的来源ID。
- 保存输入快照、筛选、实际模型、状态及结果。相同范围与数据重复提交复用已完成结果；刷新不调用模型。
- 来源变化时提示旧结果未包含更新，可显式重新生成。
- 原规则卡片折叠，只作为规则辅助线索，不冒充 AI 综合结论。

## 验收

合成 SQLite 与确定性模型替身测试：历史关联、KPI缺年、未发布场景、工况回读、三批归并、覆盖校验、
非法来源、无效JSON失败、HTTP触发与查看、重复提交不重复调用、来源变化提示。
未使用真实内部数据或实际模型服务；不宣称真实模型结论质量及 Windows BAT 已实机验证。

## 使用

累计升级至原基线目录，保留原配置和数据库，仍使用原 BAT 启动。
进入“场景资产与业务洞察”，先应用筛选，再点击“生成 / 查看本范围解读”。
结果为待人工评审建议，不自动合并或发布场景，不建立治理工单，不代表实测达标。

## 边界

默认模型输出额度使用 scenario_interpretation_max_tokens，未设置时为8192。
单条证据超过22000字符时明确失败，不静默截断；批次摘要无法继续归并时同样失败。
后台线程不是独立任务队列，生成期间应保持应用运行。异常等待可以手动停止后重试；迟到响应不会写入完成结果。
尚未实现中途重启续跑、分批结果断点复用；停止等待不能取消已发出的服务器模型请求。
AI结果需要人工评审；来源ID完整性校验不能证明语义判断必然正确。
