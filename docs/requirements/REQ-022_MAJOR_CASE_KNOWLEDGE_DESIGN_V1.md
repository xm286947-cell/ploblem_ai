## 1. 目标与边界

在现有系统新增独立文档知识库，以重大复盘 PDF／Word 为试点，完成：材料接入 → 自动关联 ITR → Skill 提取 → 人工确认 → 旧 Repeat Case 检索、分析与报告。后续文本、标准、操作指导通过专项 Skill 扩展，不重复建设底座。

本次仅归档设计，不修改业务代码、运行数据、现有启动入口和模型配置。现有单问题逆向 Demo、场景、画像保持原状；本方案不自动取代 CURRENT_PHASE_DEMO_BASELINE.md 的执行范围。用户明确启动本需求后再按本方案实施。

不做：复杂智能体编排平台、审批治理、自动发布场景、全量历史重跑、Docker/MySQL迁移。Skill 是应用内配置，不等同于 Codex 开发技能。后续执行沿用用户指定 Sol 的交接约定；文档不会切换模型。

## 3. 业务对象与计数

- 问题事件：一次发生；ITR、CS、漏测可以是同一事件的不同证据。
- 案例：一次专项复盘，可覆盖多个事件、多个附件。
- 文档：独立材料及不可变版本，不等于一次问题。
- 知识条目：事实、机理、根因、措施、验证等可引用内容。
- 重复关系：不同事件间的分析结论，独立于同号资料关联。

案例数、文档数、知识数和问题事件数分别统计。一个重大案例关联多ITR时保留各事件边界，不把客户、工况和设备混成一个事实。没有ITR允许建案例，用内部ID管理；不凭相似标题自动并案。

## 4. 存储设计

保留业务库，新增一个 knowledge.sqlite3（建议名）；不按材料类型拆库。附件与旧引擎兼容工件位于配置的数据目录，而非源码目录。所有新目录不纳入Git，不默认打包运行数据。

建议目录：data/knowledge/knowledge.sqlite3、data/knowledge/attachments/、data/knowledge/legacy_runs/<run_id>/。实际根路径可配置，用相对附件路径兼容Win10和Linux，不硬编码Mac路径。

以下均为拟新增逻辑表，并非已实施DDL：

| 表 | 关键内容／约束 |
|---|---|
| kb_schema_version | 独立数据库迁移版本 |
| kb_case | 案例ID、类型、标题、领域、分组、状态、旧案例ID映射 |
| kb_document、kb_document_version | 逻辑文档与版本；hash、附件路径、类型、解析状态；版本不可变 |
| kb_case_document | 案例与材料多对多关系；正文/补充/参考角色 |
| kb_fragment | 材料版本、片段序号、章节、页码或段落定位、文本/表格；唯一(version_id, ordinal) |
| kb_source_link | 案例、来源系统、类型、record_id、来源分组、版本、标准ITR、关联角色、确认状态 |
| kb_entry、kb_entry_revision | 知识类型、摘要、适用条件、限制、扩展JSON、事实/推断/缺失、确认状态；修订可追溯 |
| kb_evidence | 条目修订到片段或业务来源快照的引用、定位及必要摘录 |
| kb_tag、kb_tag_link | 标签命名空间、编码、候选/启用状态；关联唯一约束 |

| kb_run、kb_step | 输入清单/hash、Skill/模型/解析器版本、状态、时间、覆盖数、错误和阶段结果 |

高频筛选内容使用固定列和索引，不在列表中扫描大JSON；专项字段用JSON扩展。分组+标准ITR、来源定位键、案例状态、文档hash、片段版本序号、条目类型及任务状态建索引。索引设计在M1用查询计划验证。

附件同组内容hash去重；不同分组可复用底层文件但不得泄露另一组的存在或内容。第一版可按组分别保存，优先保证隔离。文件去重不等于文档修订识别：不同内容需用户指定修订关系，不能仅凭文件名覆盖。

## 5. 跨库读写与关联

知识库保存来源引用，业务库仍是ITR/CS/漏测事实的权威来源。跨库没有数据库外键保障，服务层负责校验、失效标记和对账。

新增 BusinessSourceGateway（拟名）：批量读取指定分组的来源摘要、版本和证据。列表先各查各库，再批量补当前页标签；详情按需取证据。禁止逐行查询和跨库全量原文联查。ATTACH只作为封装内可选只读手段，不扩散到模板和各业务模块。

自动匹配：清单明确ITR → 沿用标准化及允许关联规则 → 唯一命中关联；多命中待确认；未命中待匹配。文档提到的ITR先标本案/历史引用/不确定，后两者不得自动给对应事件打“重大问题”。后续导入后支持补匹配，不更改旧来源。

分析时在知识库保存最小必要输入快照及来源版本；不复制整份业务库。源记录更新标STALE待复核，删除标SOURCE_UNAVAILABLE；历史分析仍可查，但不充当最新事实。不同字段分别保留ITR现场事实、CS最终措施、漏测原因和复盘系统性结论；冲突显性展示，不设置“一种来源覆盖所有字段”。

任务写入只在知识库提交，业务库原则上只读。关系标签由知识库当前有效关联批量派生，不要求跨库同时写标签。界面保留用户关心的重大问题、有CS、有漏测、有PDF和待匹配标签；重复标签只来自人工确认的重复关系。

## 6. Skill契约及阅读策略

表单配置：skill_code/version、材料类型、必读章节、辅助章节、可引用业务来源、扩读条件、提取字段及schema、证据要求、标签词典、缺失处理、输入输出预算。配置修改产生新版本；任务固定版本，不能运行中静默变更。配置仅允许受支持策略，不允许任意执行脚本或外部命令。

重大复盘Skill必读：问题经过、根因/机理、措施、验证；缺失章节需输出缺失，不能补成事实。先识别全文结构再选片段；一个片段允许支持多个条目，保存实际阅读清单。Word定位用标题路径、段落/表格序号，不虚构稳定页码。V1新增DOCX解析适配，旧DOC明确提示另存DOCX，不默默声称所有Word格式都支持。

输出每项包含：类型、内容、适用范围、限制、证据引用、事实/推断/未知、待确认项。文档中的指令属于待分析内容，不能覆盖Skill规则；模型不得任意读取整个数据目录。确认在知识条目层进行，原文与模型输出不覆盖人工修订。

首批Skill：major_review_extract；repeat_case_analyse（调用旧流程）。标准和操作指导仅留契约，不纳入首轮实现。

## 7. 任务、上下文和恢复

步骤：接收校验 → 解析 → 文档结构识别 → 片段提取 → 证据校验/合并 → 待确认 → 入检索范围。每阶段记录覆盖清单。

任务状态：QUEUED/RUNNING/PARTIAL/FAILED/COMPLETED/CANCELLED；人工确认状态独立。有效输出可以包含明确缺失；必读片段存在但未处理或JSON未通过校验不能标COMPLETED。

按章节和token预算切分，预留输出预算；截断或格式错误只有限重试/缩小分片，不无限加大token。每步幂等键含材料内容hash、关联证据版本、Skill版本、解析器版本、模型配置及步骤参数。输入不变复用成功步骤；变化时仅失效受影响步骤和后继结果。保存失败原因、覆盖数量、原文定位和可继续入口；取消不丢已完成步骤。

## 8. 原Repeat Case兼容路径

重大知识库 → LegacyCaseAdapter（拟名）→ 旧schema工件 → 原检索/M8.1/M8.2/M8.3/M8.4/M8.5 → 结果校验 → 知识库记录。

M0先确认所有旧runner对project_root、配置、prompt和索引的依赖。第一版采用隔离run目录导出已授权的案例快照和查询工件；原仓库knowledge/与output/不得成为新任务共享写入位置。兼容工件是可重建缓存，不是第二个权威知识库。

旧Standard Case的单itr_id不足以表达多事件：分别构造事件证据视图，内部ID映射到case_id+event_id+revision；只绑定明确属于该事件的内容，共享复盘结论另有证据标记。不能把多个ITR拼成一个号，不能将无法分配的事实复制到每个事件。无ITR案例用内部事件ID，缺失业务字段按旧schema允许方式表达，不伪造编号；不兼容则阻断适配并提示。

保留原判定枚举和规则。系统展示重复/疑似/相关/证据不足；NEW_CASE展示“当前候选范围未发现同类重复”，不扩大为全球新问题。相似性、重复性、方案复用分别展示。候选必须排除当前事件及同事件资料、旧版本，遵守分组范围；历史时间未知须标记，不能声称已整改后再次发生。

已有旧案例迁入为显式导入任务：先预览、schema校验、保留旧ID和版本、确认后入库。旧AI分析默认待确认，不冒充人工认可；默认不重跑旧提取。迁入幂等，不覆盖新库修订。

## 13. 按任务选择模型（2026-09-19补充）

用户确认不统一使用Astra，开发模型与产品运行模型分开配置。本节细化前述Sol交接规则，不自动切换会话模型或修改产品模型配置。

### 开发任务

- Sol主导：按方案完成M0–M4的常规开发、适配、迁移、测试与修复。
- Astra按需：复杂架构决策、跨模块疑难定位、关键方案及结果审查，不全程默认使用。
- 轻量模型候选：文档整理、简单文案和机械性修改；须校验，具体型号按可用性选择。
- 升级条件：常规模型无法通过验收、出现跨模块冲突或关键证据争议时升级处理；不得静默改变需求范围。

### 产品运行任务

- 解析、编号规范化、匹配、去重、结构校验由程序完成，不强制调用模型。
- 文档分类、标签建议、简单字段提取优先评测低成本模型。
- 复杂复盘证据融合和重复问题判断选择通过专项评测的模型；难例可升级，证据不足不能靠换模型编造补齐。
- Skill定义业务规则及能力需求，执行配置绑定模型档案；不将某厂商型号写死在Skill正文中。
- 每次任务保存模型标识、参数、Skill版本、输入版本、耗时及可获得的token使用；模型改变后不得无条件复用不兼容步骤。
- 以合成/脱敏固定案例比较证据正确性、遗漏、格式通过率、耗时及成本，再决定默认模型。不把上述分工当作已完成的模型性能验证。

总体原则：程序优先、常规模型主导、复杂任务升级、依据验收选型。自动多模型路由暂不作为首轮必须功能，可先人工选择模型档案。
