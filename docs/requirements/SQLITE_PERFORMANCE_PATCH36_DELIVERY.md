# SQLite 性能优化 PATCH36 交付说明

## 目标

在不改变 Windows BAT 启动方式、不迁移数据库、不接触真实业务数据的前提下，缓解 600MB 以上 SQLite 数据库的列表查询、场景筛选和看板加载缓慢问题，并降低短时锁冲突。

## 已完成

1. 软件考核及其他材料工作台改为 SQLite 内完成搜索、领域/月/年筛选、总数计算和分页；只解析当前页 JSON，不再读取最多 10 万条后反复解析。
2. 场景列表的编号、状态、生成批次、业务活动和适用范围筛选下推至数据库；场景详情按场景编号精确读取。
3. 场景范围选项改由 SQLite JSON 提取，不再把全部彻底解决单原文搬入 Python 逐条解析。
4. 场景资产看板在单次请求内复用场景与问题事实，取消循环内逐场景查询。
5. 增加材料分组、ITR、关联关系、考核年份、场景状态、活动、范围、证据及能力缺口索引。
6. 统一关键仓储连接参数：忙等待 10 秒、32MB 页面缓存、内存临时表；不强制切换 WAL。
7. 提供 `scripts/sqlite_health_report.py` 只读检查工具，可输出库体量、空闲页、完整性、表行数和索引清单。

## 安全边界

- 不删除、不归档任何业务数据。
- 不自动执行 `VACUUM`、`REINDEX` 或日志模式切换。
- 不修改 SQLite 文件路径和 BAT 启动入口。
- 真实 Windows 数据库的最终耗时仍需在公司环境验收；本地只使用测试库验证功能与查询边界。

## 验收结果

- 全量自动化测试：480 项通过。
- 新增专项验证：材料查询不调用整库读取；240 条合成材料的组合筛选和分页正确；120 条合成场景的精确查询和范围筛选正确。
- 原有导入、年份修正、场景生成、场景资产和画像页面回归通过。

## 上线后建议

首次用 BAT 启动新包时，程序会以 `CREATE INDEX IF NOT EXISTS` 补建索引。应先备份数据库，并给首次启动预留索引创建时间；完成后后续启动不会重复重建。若仍慢，先运行只读健康报告并记录具体页面与耗时，再决定是否进入归档或维护阶段。
