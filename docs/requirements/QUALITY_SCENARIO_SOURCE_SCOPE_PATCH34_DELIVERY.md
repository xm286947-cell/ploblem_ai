# PATCH34：AI质量场景候选取数边界修复

日期：2026-09-06。目标基线：`v1.1-p2-rc2-full-20260901`，累计包含 PATCH33。

## 问题原因

候选生成页原先把“采用的产品场景词典”与“源问题产品范围”混在同一交互中。产品代码只用于选择生命周期/业务活动词典和辅助匹配漏测分析，并未过滤彻底解决单或 ITR；默认来源又覆盖软件、硬件和机械，导致按一个月预览时可能出现数百条跨领域问题。

## 完成内容

- 将“场景词典”“问题领域”“源数据产品/产品线”拆为独立条件。
- 彻底解决单/ITR入口默认只筛选软件问题；硬件、机械和领域未识别数据必须人工切换后查看。
- 软件考核入口固定标识为软件问题，并继续按照数据运营 KPI 计入年份和月份筛选。
- 问题领域优先读取源数据明确字段；缺失时只使用软件、硬件器件或机械结构化字段及已关联漏测问题的领域，不根据问题描述关键词猜测。
- 源数据产品范围读取产品类型、产品线、产品系列或产品编码；与人工指定的场景词典互不替代。
- 预览页展示同一 ITR 去重后的问题数、软件/硬件/机械/未识别构成、数据来源构成及漏测分析覆盖情况。
- 同一 ITR 的彻底解决单优先，ITR仅补充缺失事实，不作为第二条问题重复分析。
- 提交生成任务时使用相同的领域、源产品、组织、型号和年月条件重新核验，范围变化时拒绝启动并要求重新预览。

## 验证结果

- 场景来源专项回归：12 passed。
- 项目主测试集：477 passed。
- 覆盖软件默认隔离、硬件显式切换、源产品过滤、结构化领域识别、软件考核取数、ITR去重及生成快照一致性。
- 未修改或使用真实内部数据；目标 Windows 数据库中的实际数量需升级后通过页面预览确认。

## 升级方式

停止 BAT 服务并备份程序目录与 SQLite 数据库；将 PATCH34 累计升级包按原目录结构覆盖，然后继续使用原 BAT 启动。完整安装可使用 20260906 R4 完整包。
