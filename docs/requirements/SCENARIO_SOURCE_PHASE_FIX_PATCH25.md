# PATCH25 场景阶段与软件考核来源修复

## 使用

停止旧进程，备份后按累计补丁说明覆盖程序文件，继续使用原BAT启动。
软件考核工作台点击“按考核范围生成质量场景”，也可从质量场景库进入AI生成候选。
数据来源默认软件考核；保留原漏测入口。选择的产品指定场景词典，不替代型号筛选。
支持IPMT、SPDT、型号、考核年份与月份范围联合筛选，预览后人工选择问题。
KPI计入月份若含2026-08等年月则解析；只有8月且无独立考核年份时为“未知”，不从ITR号推断考核年份。

## 输入优先级与隔离

仅软件考核SW-OPS组作为新入口，不写入漏测问题库。按ITR编号规范化关联；彻底解决单末尾CS不影响匹配。
同单多组或多漏测记录无法唯一判定时显性提示，不任意选一条。
事实优先彻底解决单；漏测发生、流出结论优先；未提供的发生原因可用彻底解决单原因/TRC补充。未提供流出原因保持缺失。
来源标签：有漏测分析、部分漏测并补充、无漏测基于彻底解决单、依据不足。
候选证据保留考核原单、彻底解决单、漏测单链接、字段来源和输入快照；重试使用相同快照，防止源数据更新改变原任务口径。

## 阶段判断

运行执行关注单系统任务，系统联动关注必要的跨系统交互，长稳运行关注必要的时间/循环/资源累积。
AI须比较三个阶段的证据，说明主阶段并保留其他工况。原发生阶段仅供参考。
取消宽泛关键词强制改为运行执行。生命周期/业务活动不一致的输出进入待确认，不偷偷改分类。
阶段比较缺失或原阶段冲突显示待确认；候选仍须人工审核，不保证模型每次判断正确。
保留完整问题描述和发生/流出主要分析文本，不再按300/240字符机械截断。

## 验证与边界

临时SQLite、合成材料、确定性模拟模型验证：有/无/部分漏测、跨年考核筛选、字段优先级、真实HTTP提交、后台任务3/3候选、来源链接、输入快照及洞察事实消费。
相关回归33项通过；未调用外部模型、未处理真实内部问题。需要用户用少量已知阶段的问题确认实际模型识别效果，无需全量重跑。
历史已生成候选不会自动改写；本次没有实施行业/客户词典变体。
