# 多源质量问题分析与标准化闭环初步需求 V0.1

归档日期：2026-08-31
状态：业务思路基线，暂不冻结数据结构

## 1. 建设目标

以 ITR 问题为业务主线，贯通现场恢复、彻底解决、深度分析、标准固化和效果验证：

```text
问题发生 → 现场恢复 → 彻底解决 → 深度分析 → 共性识别
→ 标准固化 → 研发应用 → 后续 ITR 验证效果
```

系统既要回答“质量运行表现如何”，也要回答“为什么发生、为什么没有拦截、以后如何预防”。

## 2. 业务材料范围

1. **ITR 问题**：面向现场响应与恢复，同时用于分析严重程度、发生阶段、响应效率、MTTR、重复问题及薄弱环节。
2. **ITR 彻底解决单**：记录最终根因、永久措施、验证和关闭结论。
3. **漏测分析数据**：开发与测试进一步分析形成的高质量数据，是当前深度洞察的主要依据。
4. **重大问题复盘**：材料完整，适合深度案例分析与组织级改进。
5. **批量问题**：影响范围大但内容较粗，需隔离分组和专项分析，不能直接污染正式洞察。
6. **测试问题**：独立保存；额外分析范围后续另立需求。

## 3. 问题关联原则

- 以 **ITR 编号**作为业务关联主线。
- ITR、彻底解决单、漏测分析、复盘、批量问题材料、人工/AI分析和标准成果均可关联到同一 ITR。
- 同一 ITR 可以有多份材料、多次分析和多版措施，但统计问题数时只计算一次。
- 一份批量问题材料可以关联多个 ITR。
- 暂无 ITR 编号的材料先作为待关联问题保留。

## 4. 两条独立分类轴

### 4.1 材料/业务类型

ITR、彻底解决单、漏测分析、重大复盘、批量问题、测试问题。

### 4.2 问题领域

软件、硬件、机械、跨领域、待确认。

问题领域与材料类型不得混用。例如，同一个漏测分析问题可以属于软件，也可以属于软硬件跨领域。

## 5. ITR质量运行分析

### 5.1 时间指标

围绕发生、受理、首次响应、开始定位、临时恢复、根因确认、永久措施完成、验证、关闭等节点，分别计算：

- 首次响应时长；
- 定位时长；
- 现场恢复时长；
- 永久解决时长；
- 完整闭环时长。

临时恢复与彻底解决必须分开度量，不能用一个 MTTR 混淆。

### 5.2 薄弱环节

按时间、产品、严重程度、发生阶段和问题领域识别：

- 问题集中区域；
- 高严重度问题；
- 恢复慢和关闭慢的问题；
- 重复发生问题；
- 产品或组织的响应与闭环短板；
- 异常增长趋势。

发生阶段应支持安装、配置、调试、试运行、正式运行、联动、长稳、升级、回退、维护等业务配置。

## 6. 深度分析

### 6.1 质量工程能力

从需求、设计、编码、集成、测试、发布、软硬协同等环节分析为什么发生，以及技术措施能否预防再发。

### 6.2 质量管理能力

从评审、变更、基线、分支合入、已知问题、发布门禁、横向排查和效果验证等机制分析为什么未被拦截。

同一问题可以具有多个工程与管理标签。

## 7. 标准化闭环

标准化不是增加文档，而是把分析确认的风险固化为可执行、可验证、可准入的规则。

重点来源包括批量、重复、重大、高损失、必现、兼容性、非标变更和明确工程机理问题。

成果可以包括：

- 设计标准；
- 场景质量标准；
- 测试与验证标准；
- 发布准入标准；
- 变更与派生规则；
- 兼容性规则；
- 检查表、评审模板、自动检测和系统门禁；
- 可供正向风险评估复用的案例。

每项成果需说明来源问题、适用范围、责任人、执行阶段、验证方式、版本和实施效果，并使用后续 ITR 验证同类问题是否下降。

## 8. 洞察分层

1. **质量运行洞察**：主要依赖 ITR 客观数据，呈现数量、趋势、严重度、发生阶段、MTTR、重复问题和薄弱环节。
2. **深度能力洞察**：主要依赖漏测分析、重大复盘和确认后的专项分析，呈现发生/流出原因、工程与管理关键矛盾。
3. **标准化洞察**：呈现标准机会、标准缺口、成果覆盖、实施状态和实施后的问题变化。

所有报告必须显示数据范围、时间、产品、问题数、完整度、AI覆盖率和人工确认比例，并区分客观事实与推断结论。

## 9. 阶段路线

1. 第一阶段：通过 ITR 编号形成统一问题视图，并保持现有漏测分析业务稳定。
2. 第二阶段：建设 ITR 运行指标、MTTR 分段与薄弱环节识别。
3. 第三阶段：完善重大、批量和测试问题专项分析以及工程/管理双维度洞察。
4. 第四阶段：建设标准识别、成果管理、研发应用和效果验证闭环。

## 10. 当前边界

- 本文先冻结业务思路，不在此阶段决定数据库表结构。
- 第二阶段不重做现有问题分析页面和业务流程。
- 未确认时间字段定义和数据完整度前，不输出伪精确 MTTR。
- 测试问题的额外分析暂不展开，后续独立立项。
