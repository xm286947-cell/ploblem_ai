# 本范围综合解读分层归并 JSON 稳定性 PATCH47

## 问题原因

第二层归并输入的是第一层完整主题结果。原实现按与原始问题相同的字符预算拼批，而且格式失败后原样重试；随着主题正文累积，模型可能在JSON闭合前达到输出Token上限，重复请求仍然失败。

## 修复内容

- 原始问题分析批次与归并批次采用不同预算。
- 每个归并批次最多4个下层结果、输入最多12000字符。
- 归并结果最多8个主题，各主题关键段落最多220字。
- 禁止在正文重复抄写来源ID，来源只保留在 `evidence_ids`。
- JSON不完整或格式失败后，第二次调用增加紧凑JSON重生成指令，而不是原样重试。
- 接口明确返回 `max_tokens` / Token上限 / 截断时，同样进入紧凑重生成。
- 代理失败、超时等连接问题不冒充JSON问题。
- 默认综合解读输出额度由8192提高到12288；仍可用 `scenario_interpretation_max_tokens` 覆盖。
- 失败诊断记录响应字符数和末尾80字符，便于确认是否发生截断。

## 保持不变的校验

- 所有输入问题必须进入某个主题或“尚不能归纳”。
- 只能引用当前范围内的来源ID。
- 不完整结果不得保存为完成结论。
- 不因缩短文字而删除证据覆盖要求。

## 验收

- 普通单批及多批归并继续完成。
- 首次返回未闭合JSON时，第二次调用携带紧凑重生成约束并可完成。
- 接口明确达到输出Token上限时进入紧凑重生成。
- 归并批次按最多4项拆分。
- 永久无效JSON仍明确失败，不保存结果。
