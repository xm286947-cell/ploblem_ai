# PATCH35：软件场景入口与场景画像业务流收敛

日期：2026-09-06。目标基线：`v1.1-p2-rc2-full-20260901`，累计包含 PATCH34。

## 最终业务规则

### 软件质量场景候选

- 唯一选题入口为“软件问题考核工作台”。
- 选题范围由软件考核记录决定，以数据运营 KPI 计入年份和月份为时间口径。
- 支持按 IPMT、SPDT、产品型号、KPI年份和月份过滤并人工勾选。
- 场景词典只决定 AI 使用哪套生命周期和业务活动，不承担源数据过滤。
- 同号彻底解决单、ITR和漏测分析只作为关联证据：问题事实优先彻底解决单，原因及漏测分析优先使用已完成的漏测分析；证据缺失时显式标记。
- 关联证据不得增加、删除或替换软件考核选题，候选数以软件考核记录为准。

### 客户/行业场景画像

- 与软件质量场景候选分离，作为独立业务流。
- 后续可由人工选择 ITR、彻底解决单或其他数据范围后触发画像分析。
- 不在软件候选页面提供来源、领域和画像数据切换，避免业务口径混用。
- 当前保留“场景资产与业务洞察 → 客户/行业质量画像”的人工入口；原始多源画像范围的进一步扩展单独验收。

## 本次修改

- AI候选页固定显示“软件考核工作台”，移除数据来源、问题领域、源数据产品和ITR数据组选择。
- 页面只展示软件考核范围数量、已关联彻底解决单数量、漏测分析覆盖和无漏测分析数量。
- 列表时间列明确为“KPI年月”。
- 后端忽略旧链接携带的 `source=cs_itr` 等参数，仍只读取软件考核记录。
- 提交时按相同KPI、组织和型号条件重新校验选中记录，防止范围漂移。

## 验证标准

- 软件考核月份内有多少条符合筛选的唯一记录，预览就显示多少条；CS/ITR数量不改变该结果。
- 即使旧地址携带 `source=cs_itr`，候选页也不得把CS/ITR问题作为选题。
- 关联到CS、ITR或漏测分析后，只改变“分析依据”与候选内容，不改变选中问题主键。
- 继续使用原 BAT 启动方式和 SQLite 数据库。
