# PATCH58：单问题逆向质量分析 Demo

## 本轮交付

- 从 ITR、彻底解决单或软件考核问题详情进入“单问题逆向分析”。同一 ITR 合并读取，彻底解决单优先、ITR 补缺；漏测分析仅作为独立证据来源，不改写原始数据。
- 人工选择产品场景词典后触发默认模型，按客户体验、场景还原、失效逻辑、质量能力短板、指标与验证建议五层保存结构化结果。原问题发生阶段只作证据，不直接映射。
- 每个非空 AI 字段必须引用真实输入证据。根因只能直接引用原单根因字段；参与系统/设备只能从结构化产品/设备信息继承；没有证据的字段留空。业务活动与生命周期须匹配当前产品启用的词典。
- 原始事实、AI 原值、人工修订分别保存；可逐字段确认、修改、驳回。现有质量场景匹配可人工判定“已覆盖／部分覆盖／未覆盖／待核对”，保留判定依据与缺失条件及审计记录。
- AI 不自动新增或发布质量场景、标准、指标。单问题记录存入独立表，同一标准 ITR 唯一；审核后不允许 AI 静默覆盖。

## 使用与验收

进入任一原始问题详情，点击“进入单问题逆向分析”，核对左侧原始事实，选择产品词典并触发分析。右侧逐项核对证据、修订结果，最后确认场景匹配。只有核心字段、非空字段与匹配状态均得到人工确认，记录才标为 `CONFIRMED`。

本地自动化验收使用合成问题与模拟模型，覆盖页面入口、事实来源、六阶段与业务活动词典匹配、虚构根因拦截、无证据拦截、硬件问题边界、逐字段修订及匹配审计。真实模型输出质量和 Win10 BAT 启动尚需在用户环境实测，不以模拟结果代替。

## 本期边界

不做多问题聚合、质量画像扩展、正逆向自动比对、正式场景发布和治理闭环。后续可按产品／客户／行业／阶段／活动／特性／失效模式聚合本表记录，但必须继续保留原始证据下钻。
