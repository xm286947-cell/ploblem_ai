# V0.8.0-RC3 验收说明

## 目标
RC3 解决“识别信息很多，但用户第一眼看不到结论”的问题。在 RC1/RC2 的 Markdown、文档身份和 Reviewed Specification 基础上新增结果层，不改变 Raw Candidate 的可追溯性。

## 新增结果层
每个器件持久化一份 `device_conclusions`，包含：
- 写入寿命结论（Lifetime Summary）
- 诊断能力结论（Diagnostic Summary）
- 软件关注（Software Recommendation）
- 关键规格缺口 / 风险
- 最多 8 个 P0/P1 关键规格及其证据
- 结论状态：complete / partial / insufficient

结论由 Reviewed Specification 规则化生成，不直接根据 Raw Candidate 编写，也不绕过人工确认。

## 四类器件结果口径
- NOR Flash：P/E、Retention；Status Register、Program/Erase Fail、Error Flag、ECC（若支持）；缺少直接寿命计数时提示软件维护擦写统计。
- NAND Flash：Cell Type、P/E、Retention；ECC、Bad Block、Program/Erase Fail、Status/Read Retry；当前未识别直接寿命计数时明确提示。
- eMMC：默认用户区/Enhanced Area、P/E（若有）；EXT_CSD Life Time A/B、Pre-EOL、BKOPS 等健康能力。
- SSD：TBW、DWPD、Endurance；SMART/NVMe Health、Percentage Used、Data Units Written、Available Spare、Media Errors 等。

## 页面信息架构
默认页由原“寿命与诊断大表”调整为：
1. 分析结论
2. 关键规格
3. 料号差异
4. 证据
5. 识别明细

“分析结论”第一屏只展示三张卡：写入寿命、诊断能力、软件关注；原始 Agent 候选仅在“识别明细”出现。

## 自动刷新
以下动作后会自动重建 Reviewed Specification 和 Device Conclusion：
- PDF 参数导入完成
- Final Review 修正候选
- 人工确认 / 驳回候选
- 删除单条候选

清空当前参数时同步清除结论；下一次形成审核后规格时重新生成。

## 新增接口
- `GET /api/devices/{id}/conclusion`
- `POST /api/devices/{id}/conclusion/rebuild`
- `GET /api/devices/{id}/family-view` 现在同时返回 `conclusion`
- `GET /api/devices` 增加 `conclusion_status`
